这个工作区里，AI 要记的东西都在文件里：规则在 AGENTS.md，进度在各项目的 STATUS.md，跨项目的经验和偏好在 `memory/`。不管你是哪个 agent，照下面做就能接上活。

## 接着做

用户说「接着做」「继续」时：

1. 先读 `memory/MEMORY.md`（用户偏好和跨项目经验，一行一条，用得上再点进去看）。
2. 当前就在某个项目目录里 → 读这个项目的 `AGENTS.md` 和 `STATUS.md`，从「下次入口」开始干。
3. 在工作区根目录、用户没说哪个项目 → 按修改时间找最近的 2–3 个 `STATUS.md`（项目索引里标 🚧 的优先），报项目名和各自的「下次入口」，问一句接哪个。只有一个候选就直接开工。
4. 收工前按下面的「更新协议」更新 STATUS.md，下一个接手的人（或 AI）就靠它。

## 目录

| 目录 | 放什么 | 规矩 |
|------|--------|------|
| `projects/` | 自己的项目，可再按类别分子目录 | 可以放手改 |
| `forks/` | fork 来的开源项目 | 改动要能合回上游；上游自带的 AGENTS.md 不动 |
| `vendor/` | 只看不改的参考代码 | 只读 |
| `notes/` | 跨项目笔记，索引是 `notes/_index.md` | 先查索引，有就更新，没有再新建 |
| `memory/` | 用户偏好与跨项目经验，索引是 `memory/MEMORY.md` | 一条一个文件，索引里一行 |
| `_archive/` | 不再用的东西 | 只往里挪，不删 |

新项目放进对应目录，建好 `AGENTS.md`（`CLAUDE.md` 软链过去），再在下面的项目索引加一行。

## 每条信息只有一个家

| 信息 | 放在哪 | 别的地方最多出现 |
|------|--------|------------------|
| 项目是什么、技术栈、怎么跑 | 项目 `AGENTS.md` | 项目索引里的一句话 |
| 做到哪了、下次从哪开始、待决策 | 项目 `STATUS.md` | 不进任何索引 |
| 做过什么、哪天做的 | git log、STATUS.md 底部「归档」 | 哪都不出现 |
| 用户偏好、跨项目经验 | `memory/` 子文件 | `MEMORY.md` 一行钩子 |

同一段话不写进两个地方。

## 文档预算

| 文件 | 上限 | 超了怎么办 |
|------|------|-----------|
| 本文件 | 200 行 / 10KB | 细节挪进项目文件或 notes，这里留一句和路径 |
| `memory/MEMORY.md` | 150 行 / 12KB | 合并、退休旧条目（Claude Code 只读前 200 行或 25KB，后面的会被悄悄丢掉） |
| 项目 `AGENTS.md` | 200 行 | 参考材料拆到 docs/，进度挪到 STATUS.md |
| 项目 `STATUS.md` | 主体 100 行 | 过时的进展挪到底部「归档」 |

超预算时先瘦身再写，不要直接往后加。

## 更新协议

有实质进展时，从下往上更新，越往上写得越少：

1. 项目 `STATUS.md`：详细进展只写这里。
2. 项目 `AGENTS.md`：只在项目本身变了时改（依赖、命令、结构、活跃文档清单）。
3. 本文件的项目索引：只在状态标签变了时改状态那一格。
4. `memory/`：只在出现跨项目也用得上的经验或用户偏好时写，并在 `MEMORY.md` 加一行。写在工作区的 `memory/` 里，不要只记进某个 AI 自己的记忆目录（比如 Claude Code 的 `~/.claude/projects/…/memory/`），换个 AI 就读不到了。

## 写作规矩

- AGENTS.md 只写现在时，半年后还成立的才写。STATUS.md 写「现在做到哪了」。带日期的过去时只进 git log 和归档区。
- 索引行只帮下个会话决定要不要点进去：名字、路径、一句话（≤30 字）、状态。不写日期、版本号、功能清单、形容词。
- 写之前看一眼周围条目有多长，别比它们长。遇到超长的旧条目，先把它剪短再写自己的。

## 安全

- 删除或覆盖文件前先列清单问用户；「删除」默认是挪进 `_archive/`。
- 密钥、令牌、密码不写进任何 Markdown。
- `vendor/` 只读；`forks/` 里上游自带的规则文件不改。
